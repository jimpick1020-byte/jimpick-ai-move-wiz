# 고객 사전정보 입력 링크

업체가 방문견적 전에 고객에게 보안 링크를 보냅니다. 고객이 로그인 없이 기본정보·주소·큰 가구/가전을 입력하면, 해당 업체의 견적 초안 한 건이 자동으로 채워집니다. 기존 고객·견적·계약·품목·사진·달력·문자 기록은 건드리지 않습니다.

## 기존 구조 재사용 (중복 테이블 없음)
- 견적 초안: 지금 쓰는 견적 초안 저장소(`estimate_drafts`, 업체별 `user_id`)에 기존 견적과 같은 모양으로 저장합니다. 그래서 기존 견적 작성 화면이 그대로 엽니다.
- 보안 토큰: 직원 공유 링크와 같은 방식을 씁니다(32바이트 무작위 토큰, 해시만 저장).
- 문자: 지금 쓰는 알리고 서버 발송과 발송 기록(`estimate_deliveries`)을 그대로 씁니다. 발신번호는 01075662542로 고정하고, 문의번호는 업체 연락처를 쓰고 없을 때만 01075662542를 씁니다.
- 주소 검색: 지금 쓰는 카카오 주소 검색을 씁니다.
- 고객 링크 품목 카드: 업체 품목(`item_icons`)과 비공개 이미지 저장소 `item-icons`를 그대로 쓰고, 표시 설정만 추가합니다.

## 새로 추가할 것
1. **요청 기록 테이블 `intake_requests`** (업체별): 고객 이름·전화, 토큰 해시, 상태, 만료일, 연결된 견적 ID(업체마다 고유), 고객 입력 내용, 처음 열람·작성 시작·처음 제출·최근 수정 시각, 수정 횟수, 확정 시각, 사장님 읽음 여부, 동의 시각.
2. **`item_icons` 열 추가** (기존 값은 그대로): 고객 링크 표시 여부, 폐기물 선택 가능 여부, 표시할 방, 고객 링크 표시 순서.
3. **사장님 화면**
   - 고객 관리 카드: 전화·문자 옆에 파란 「사전정보 요청」 버튼과 상태 표시(미발송·발송 완료·고객 열람·작성 중·입력 완료·사장님 확인 완료·만료·취소).
   - 견적 시작 화면 맨 위: 「고객 사전정보 요청」 버튼(신규 고객은 이름·전화만 입력).
   - 요청 창: 이름, 전화, 상태, 문자로 보내기, 카카오톡으로 보내기(휴대폰 공유창), 링크 복사, 다시 보내기, 링크 취소, 제출 내용 보기, 견적 초안으로 이동, 사전정보 확정.
   - 앱 알림: 「○○○ 고객님이 사전정보 입력을 완료했습니다.」 (앱을 열 때와 화면에 있을 때 확인).
   - 견적 목록에 「사전정보 입력 완료」 표시.
   - 설정 안에 「고객 링크 품목 관리」: 이름, 그림, 카테고리, 표시할 방, 표시 여부, 폐기물 가능 여부, 순서. 새 카드는 기존 「품목 직접 등록」 저장 방식(이미지 먼저 업로드, 실패하면 정리)을 그대로 씁니다.
4. **고객 화면 `/intake/$token`** (모바일 전용, 관리자 메뉴 없음, 큰 글씨)
   - 맨 위 안내 문구와 1/2/3 진행 표시, 아래에 「이전」·「다음」 버튼 고정.
   - 1단계 이름·전화·날짜·희망 시간 / 2단계 나가는·들어가는 주소와 상세주소 / 3단계 방(거실·안방·작은방·부엌·베란다·기타)과 큰 품목 카드 3열.
   - 한 번 누르면 선택, 다시 누르면 해제, 두 번 빠르게 누르면 폐기물(흐린 빨간 배경, 큰 빨간 X, 「폐기물」). 짧은 대기시간으로 겹침 방지, 진동. 점 3개 메뉴로도 전환할 수 있습니다.
   - 입력할 때마다 서버에 임시 저장합니다(작성 중 상태).
   - 확인 화면, 개인정보 동의, 「기본정보 입력 완료」, 완료 문구. 확정 후에는 마감 문구만 보입니다.
   - 톤수, 루베, 금액, 엘리베이터, 사다리차는 보이지 않습니다.

## 견적 초안 연결
- 처음 제출하면 견적 ID를 하나 만들어 요청 기록에 고정합니다. 다시 제출하거나 수정하면 같은 견적 초안만 고칩니다. 업체와 요청마다 하나만 생기도록 데이터베이스에서 고유 조건으로 막습니다.
- 고객이 넣은 이름, 전화, 날짜, 시간, 주소, 층수와 방별 품목·폐기물(기존 폐기 표시 구조 사용)을 채워 넣습니다. 엘리베이터·사다리차는 「방문 후 결정」으로 비워 둡니다.
- 사장님이 견적 초안을 직접 수정한 뒤에도 고객 수정이 들어오면, 고객이 입력하는 칸만 덮어씁니다(사장님만 입력하는 칸은 보존).
- 확정 후에는 고객 수정을 서버에서 막습니다.

## 층수
- 고객 링크 전용 엄격 규칙: 「3층」, 「지하 1층」, 「B1」처럼 층이 직접 적힌 경우만 자동으로 넣습니다. 「502호」는 층수로 판단하지 않고 「방문 확인 예정」으로 둡니다.
- 사장님 화면의 기존 층수 자동 입력(호수로 추정)은 바꾸지 않습니다.

## 권한
- 업체: 자기 요청만 만들기·보기·고치기(RLS: `company_id = auth.uid()`). 플랫폼 관리자는 전체 조회만 합니다.
- 고객: 로그인 없이 서버 함수만 씁니다. 토큰 해시로 한 건만 찾고, 취소·만료되면 바로 막습니다. 데이터베이스 직접 접근은 열지 않습니다.
- 직원: 지금은 직원 계정이 없고 직원은 작업지시서 링크만 받으므로, 이번 기능은 직원에게 보이지 않습니다.
- 토큰 원문과 개인정보는 기록에 남기지 않습니다.

## 시험
- 자동 시험: 엄격 층수 추출, 한 번/두 번 누르기 상태 전환, 같은 요청은 같은 견적 ID.
- 화면 시험: 로그인된 사장님으로 요청 생성, 고객 화면을 로그인 없이 열어 3단계 입력·제출, 사장님 견적 초안 자동 입력 확인, 다시 제출해도 중복 없음, 확정 후 수정 차단, 취소 후 접근 차단.
- 문자 실제 발송은 사장님이 등록한 테스트 번호로만 한 번 보냅니다. 번호를 알려 주셔야 합니다. 실패하면 실제 알리고 오류를 표시하고 기록합니다.

## 기술 메모
- 서버 함수: `intake.functions.ts` (업체용: `requireSupabaseAuth`, 고객용: 토큰 검증 후 관리자 클라이언트 사용), 문자 발송은 `sms.edge.ts` 사용.
- 고객용 품목 이미지는 서버에서 짧은 서명 URL로 내려줍니다.
- `AGENTS.md`에 구조 규칙을 기록합니다.
