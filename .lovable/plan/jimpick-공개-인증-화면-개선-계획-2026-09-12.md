# JIMPICK 공개 인증 화면 개선 계획

## 목표
로그인, 업체 회원가입, 아이디·비밀번호 찾기, 최초 인증 확인 화면만 서비스 수준으로 개선합니다. 기존 인증·Google 로그인·비밀번호 재설정과 모든 기존 데이터는 그대로 유지하며, 로그인 이후 견적 화면은 변경하지 않습니다.

## 구현 범위

### 1. 인증 전용 화면 틀
- 인증 화면에만 쓰는 반응형 화면 틀과 상단 바를 추가합니다.
- 가짜 `9:41`, 통신·배터리 아이콘, 네온/분홍·보라 테두리, 휴대전화 프레임을 인증 화면에서 완전히 제거합니다.
- 모바일은 전체 너비와 16px 여백, PC는 최대 480px 중앙 정렬과 세로 스크롤을 적용합니다.
- 흰색에서 연한 파란색으로 이어지는 단정한 배경과 지정된 JIMPICK 색상·글자 크기를 사용합니다.
- 기존 공용 `MobileShell`, `TopBar`는 로그인 이후 화면에 영향을 주지 않도록 그대로 둡니다.

### 2. 로그인 화면
- 512px JIMPICK 로고를 선명한 크기로 표시하고 파란 헤더를 정돈합니다.
- 이메일·비밀번호에 실제 연결된 label/id/name/autocomplete를 적용합니다.
- 비밀번호 보기·숨기기, Enter 로그인, 명확한 입력/인증 오류, 접근성 알림을 추가합니다.
- 아이디 저장과 로그인 상태 유지 정책은 기존 저장 방식을 보존하고, 44px 이상 터치 영역과 공용 PC 안내를 적용합니다.
- 로그인 요청 중 버튼 잠금, 로딩 표시, `로그인 중…` 문구를 적용합니다.
- 보조 버튼 문구를 `업체 회원가입`, `아이디 · 비밀번호 찾기`로 정리하고 3일 체험 안내를 분리합니다.

### 3. 업체 회원가입
- 기존 이메일 가입과 Google 인증 호출을 그대로 사용하면서 이메일, 비밀번호, 업체명, 담당자명, 연락처의 label/id/name/autocomplete를 정비합니다.
- 연락처는 숫자만 받아 `010-0000-0000` 형태로 자동 정리하고 실시간 오류를 표시합니다.
- 비밀번호 8자 이상·영문·숫자 조건과 흔한 비밀번호 안내를 실시간 표시하고 보기·숨기기를 추가합니다.
- 필수 입력과 필수 동의 전에는 가입 버튼을 비활성화하고, 요청 중 중복 가입을 차단합니다.
- Google 공식 아이콘과 실제 오류 안내를 추가하되 현재 Lovable Cloud Google 연결 방식을 유지합니다.

### 4. 약관·개인정보 동의
- JIMPICK 서비스용 이용약관·개인정보 처리방침 초안을 접근 가능한 대화상자로 제공합니다.
- 필수 이용약관·개인정보 동의와 선택 마케팅 수신 동의를 구분합니다.
- 기존 `profiles`에 동의 상태·시각·문서 버전 컬럼만 추가하는 안전한 migration을 적용하고, 기존 신규 사용자 생성 함수가 가입 메타데이터의 동의 정보를 함께 저장하도록 확장합니다.
- 기존 행, 테이블, RLS 정책은 삭제·초기화하지 않으며 기존 사용자 값은 nullable로 보존합니다.

### 5. 아이디·비밀번호 찾기
- 현재 실제 재설정 메일 호출과 공개 앱 복귀 주소를 유지합니다.
- 연결된 이메일 label, 실시간 빈 값/형식 오류, 처리 중 잠금, 실제 응답 이후 성공 안내를 적용합니다.
- 존재하지 않는 이메일 여부를 노출하지 않는 동일한 성공 문구를 사용합니다.

### 6. 최초 인증 확인 화면
- 앱 상태에 `authChecking`을 분리해 저장 상태 복원과 실제 세션 확인이 모두 끝나기 전에는 다른 화면을 렌더링하지 않습니다.
- 중앙 로고, 로딩 표시, `로그인 상태를 확인하고 있습니다.` 문구를 표시합니다.
- 10초 이상 지연 시 재시도 버튼을 제공하며 인증 구독은 한 곳에서만 처리합니다.
- 인증 확인 후 로그인 사용자는 기존 화면, 비로그인 사용자는 로그인 화면으로 한 번만 전환해 첫 화면 깜빡임을 제거합니다.

## 기술 세부사항
- 인증 전용 UI는 별도 작은 컴포넌트로 구성해 로그인 이후 화면 스타일 변경을 차단합니다.
- 새 색상은 전역 CSS에 의미 기반 토큰으로 등록하고 인증 화면은 해당 토큰만 사용합니다.
- 비밀번호 원문은 기존처럼 인증 서비스에만 전달하며 저장하거나 기록하지 않습니다.
- 가입 동의는 `signUp`의 사용자 메타데이터로 전달하고 기존 보안 트리거가 `profiles`에 기록합니다. 이메일 확인으로 즉시 세션이 없는 가입도 동의 기록이 유실되지 않습니다.
- 데이터베이스 변경은 추가 migration만 사용하고 기존 RLS/테이블은 유지합니다.

## 검증
- 로그아웃 새로고침에서 로딩 후 로그인만 표시되고 다른 화면 깜빡임이 없는지 확인합니다.
- 빈 이메일, 비밀번호 누락, 잘못된 비밀번호, 보기·숨기기, Enter 로그인, 체크박스 터치 영역과 요청 중 잠금을 확인합니다.
- 실제 정상 계정 로그인·세션 유지·로그아웃을 확인합니다.
- 회원가입 검증, 전화번호 자동 하이픈, 비밀번호 조건, 필수 동의 차단, 약관 대화상자를 확인합니다. 실제 계정은 대량 생성하지 않습니다.
- Google 버튼이 실제 브로커 인증 요청을 시작하는지 확인하고 임의 계정 생성은 하지 않습니다.
- 재설정 빈 값/형식 오류와 실제 메일 요청 응답을 확인합니다.
- 320/360/390/430px 및 1366px에서 잘림·가로 스크롤·가짜 상태바·분홍/보라 테두리 부재를 확인합니다.
- 빌드, 브라우저 오류, 인증 네트워크 요청을 점검하고 게시하지 않습니다.
