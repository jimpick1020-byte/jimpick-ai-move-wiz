# 업체 생성 품목 영구 유지 수정 계획

## 확인된 원인
- 기존 `item_icons`는 이미 업체 계정별 영구 품목 테이블이며, 흙침대·돌침대 행과 `item-icons` 비공개 저장소 파일도 남아 있다.
- 생성 완료 시 이미지는 영구 저장소에 업로드되고 DB 행도 `ready`로 저장되므로 생성·업로드 자체가 원인이 아니다.
- 화면 목록은 현재 견적의 `draft.customItems`에 업체 품목 목록을 섞어 사용한다.
- 새 견적 완료/초기화는 `newEstimate()`로 `draft.customItems`를 빈 배열로 만든다.
- 업체 품목 서버 조회는 로그인 후 한 번만 실행되고 `iconsLoaded=true`가 유지되어, 새 견적에서 빈 목록을 다시 채우지 않는다.
- 로컬 품목 캐시는 계정별로 분리되지 않아 같은 기기에서 다른 업체로 로그인하면 잘못 섞일 위험도 있다.

## 수정 내용
1. 기존 `item_icons`를 새 중복 테이블 없이 업체 영구 품목 원본으로 유지한다.
2. 업체 영구 품목 목록을 현재 견적과 분리한 저장소 함수·병합 함수·React 훅으로 나눈다.
3. 공간별 품목 화면은 항상 기본 품목 + 로그인 업체의 활성 생성 품목을 안정적인 `item_id`로 합쳐 표시한다.
4. 새 견적, 화면 재진입, 새로고침, 재로그인, 생성 완료 직후에 업체 목록을 다시 조회한다.
5. 견적에는 실제 선택한 생성 품목의 이름·분류·이미지 경로만 스냅샷으로 남기고, 견적 초기화·삭제는 업체 품목 원본을 건드리지 않는다.
6. 생성 완료는 이미지 업로드, DB ready 저장, 전체 목록 재조회까지 성공한 뒤에만 표시한다.
7. 비공개 저장소의 영구 경로로 매번 새 서명 주소를 발급해 표시하고, DB에는 영구 경로를 유지한다.
8. 로컬 캐시는 사용자별 키로 분리하며 서버 목록을 기준으로 병합해 다른 업체 품목이 섞이지 않게 한다.
9. 점 3개 메뉴의 명시적 삭제만 `active=false`로 바꾸는 기존 규칙을 유지한다.

## 데이터 및 보안
- 기존 `item_icons.user_id`를 업체 소유 키로 그대로 사용한다. 현재 앱은 업체 계정과 사용자 계정이 동일한 소유 모델이다.
- 기존 본인 행 조회·등록·수정 RLS와 `(user_id, normalized_name)` 활성 품목 고유 색인을 유지·검증한다.
- `item-icons`는 비공개 버킷으로 유지하고 경로는 `<업체 사용자 ID>/<품목 행 ID>.png`를 사용한다.
- 기존 고객·견적·기본 품목·수량·가격·이미지 파일은 삭제하거나 초기화하지 않는다.

## 검증
- 흙침대·돌침대 기존 DB 행과 파일 연결을 다시 확인한다.
- 로그인된 390px 화면에서 목록 표시 → 새 견적 → 새로고침 → 재접속 흐름을 확인한다.
- 동일 이름 재생성은 기존 행을 재사용하는지 확인한다.
- 견적 삭제 후 업체 품목 행이 유지되는지 확인한다.
- 가능한 경우 다른 업체 세션으로 교차 접근 차단을 확인하고, 계정이 하나뿐이면 해당 항목을 미검증으로 명시한다.
- 타입 검사, 빌드 상태, 런타임 오류를 확인한다.
