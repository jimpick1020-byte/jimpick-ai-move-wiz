# 이사 전날 오후 6시 고객 안내문자 — 실제 발송·전달확인·고객확인

## 이미 있는 것 (재사용, 새로 만들지 않음)

- 예약 표: `move_reminders` (업체별 `company_id`, 이사일, 전날 18시 발송시각, 중복방지 열쇠)
- 자동 실행: 15분마다 도는 서버 작업이 `/api/public/hooks/send-move-reminders` 를 부름
- 실제 발송: 알리고 + 고정 IP 중계 서버 (키는 서버에만 있음)
- 발송 이력: `estimate_deliveries`
- 사장님 화면: 견적 상세의 「이사 전날 안내 문자」 칸

## 새로 채울 것

### 1) 발송 결과를 단계별로 구분
지금은 "발송 성공/실패" 두 가지뿐입니다. 다음으로 나눕니다.

- 발송 예정 → 발송 처리 중 → 문자업체 접수 완료 → 통신사 전달 완료
- 발송 실패 / 발송 취소 / 결과 확인 필요

알리고 **발송결과 조회**를 실제로 연결해 접수와 통신사 전달을 구분합니다.
조회로 확인되기 전에는 "전달 완료"로 표시하지 않습니다.

### 2) 고객이 문자를 열었는지 확인
문자에 고객 전용 보안 링크를 넣고, 고객이 그 링크를 열었을 때만
"고객 확인 완료"로 바꿉니다. 처음 확인한 시각은 지우지 않고,
마지막 확인 시각과 확인 횟수를 따로 남깁니다.

### 3) 문구
요청하신 기본 문구(고객명·이사 예정 시간·출발지·도착지·확인 링크·문의)로 바꾸고,
값이 없는 줄은 아예 넣지 않습니다. 길면 장문(LMS)으로 자동 전환합니다.

### 4) 누락 점검과 작업 기록
- 오후 6시 10분(한국시간)에 내일 이사 확정 건 중 빠진 게 있으면 한 번만 다시 시도
- 발송 대상이 0건인 날도 작업이 돌았다는 기록을 남겨 관리자가 확인 가능

### 5) 화면
- 달력 계약 카드: 「전날 문자 예정 / 발송 완료 / 전달 완료 / 고객 확인 / 발송 실패」 작은 표시
- 계약 상세: 발송 예정일시, 발송 요청일시, 접수일시, 전달일시, 고객 확인일시,
  받는 번호 뒤 4자리, 문자 종류, 발송번호, 실패 이유, 「다시 발송」
- 관리자 메뉴에 「전날 문자 현황」 추가 — 오늘 예정/처리 중/전달 성공/고객 확인/실패/확인 필요 필터,
  업체·고객명·전화번호·이사일 검색. 업체 사장님은 자기 업체만 보입니다.

### 6) 실패 알림과 다시 발송
실패하면 사장님·관리자 화면에 실패 사유가 그대로 보이고 「다시 발송」이 나옵니다.
여러 번 눌러도 한 건만 나가고, 이미 성공한 문자는 확인창을 띄웁니다.
네트워크 오류 같은 일시적 오류만 자동으로 1회 다시 시도하고,
번호 오류·잔액 부족·발신번호 미등록은 자동 재시도하지 않습니다.

## 기술 메모

- `move_reminders` 를 확장(컬럼 추가)하고 중복 표는 만들지 않습니다.
  추가: `delivery_type`, `scheduled_date`, `status`(accepted/delivered/unknown 포함),
  `to_masked`, `message_type`, `message_snapshot`, `provider`, `provider_message_id`,
  `provider_response`(민감값 제거 후), `error_code`, `processing_at`, `requested_at`,
  `accepted_at`, `delivered_at`, `failed_at`, `last_checked_at`,
  `view_token`, `customer_viewed_at`, `last_viewed_at`, `view_count`.
  고유 제약: `(company_id, estimate_id, delivery_type, scheduled_date)`.
- 작업 기록 표 `reminder_job_runs` 신설(실행시각, 종류, 대상건수, 성공/실패/누락, 메모).
- 서버 함수(TanStack `createServerFn`)로 목록·상세·재발송·관리자 현황을 제공하고,
  RLS 은 업체 소유자 = `company_id`, 최고관리자는 전체 조회로 분리합니다.
- 알리고 결과 조회는 중계 서버에 `POST /result` (알리고 `sms_list`/`detail`) 를 추가하고,
  서버 훅 `/api/public/hooks/check-move-reminder-results` 에서 `provider_message_id` 기준 갱신.
  중계 서버 배포 전에는 `unknown`(결과 확인 필요)로 남기고 전달 완료로 바꾸지 않습니다.
- 모든 날짜·시각 판단은 Asia/Seoul 기준(전날 18:00 KST = 09:00 UTC)으로 계산합니다.
- 크론: 발송 15분(기존 유지), 결과 조회 10분, 누락 점검 매일 18:10 KST(09:10 UTC).
- 고객 링크는 기존 견적 보안 링크에 추측 불가한 `view_token` 을 덧붙여 확인 시각만 기록합니다.

## 확인 방법

내일 이사 확정 건 2개로 대상 조회·중복 방지·각각 발송·발송번호 저장·링크 열기 전/후 상태 변화·
잘못된 번호 실패 사유·재발송 잠금·날짜 변경/취소 반영·새로고침 후 유지·다른 업체 접근 차단을
실제 데이터로 점검하고, 연결되지 않은 부분은 그대로 보고합니다.
