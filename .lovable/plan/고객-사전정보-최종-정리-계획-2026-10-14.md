# 고객 사전정보 최종 정리 계획

기존 고객·견적·계약·품목·사진·달력·결제·문자 기록은 지우거나 초기화하지 않습니다. 새 테이블은 만들지 않고, 지금 있는 표에 칸만 추가합니다.

## 0. 먼저 확인할 것 (수정 전 보고)
- 짐픽 1~4단계와 고객 화면이 각각 쓰는 화면 부품, 품목 조회 함수, 이미지 주소, 저장 함수를 표로 정리합니다.
- 지금 확인된 차이: 짐픽은 업체 품목 조회(`listItemIcons`, 고객 전용 품목 제외)를 쓰고, 고객 화면은 별도 조회(`openIntake` 안 내장 목록 + 고객 전용 행)를 씁니다. 그림이 작고 흐리거나 빠지는 원인으로 의심됩니다.

## 1. 고객 1~4단계
- 짐픽 Step1/Step2/Step3/Step6을 그대로 띄우는 지금 방식 유지. 고객용에서만 다르게 할 것:
  - 1단계: 연락처는 업체가 넣은 번호 표시(수정 불가), 이름은 고객이 직접 입력.
  - 2단계: 주소 선택 후 남는 「다른 주소 검색」 칸 숨김. 층수는 「3층·지하 1층·B1」처럼 직접 쓴 경우만 저장, 「502호」만 있으면 「방문 확인 예정」. (사장님 화면의 기존 층수 추정은 그대로)
  - 3단계: 사다리차·엘리베이터에 「방문 후 결정」 선택지(고객 화면만).
  - 4단계: 분류는 가구·가전·주방만, 「목록에 없는 품목 추가」「자주 담는 품목」 숨김.

## 2. 그림 카드
- 고객 화면도 짐픽과 같은 품목 목록·같은 조건·같은 그림 크기를 쓰도록 하나의 서버 조회로 합칩니다(고객용은 토큰 확인 후 해당 업체 것만).
- 고객 화면 전용 내장 목록과 박스 대체 그림 제거, 그림이 정말 없을 때만 대체 그림.
- 비공개 그림은 원본 크기 서명 주소, 만료 전 자동 갱신. 실패 시 저장 위치·권한·만료를 실제로 점검.

## 3. 견적 내역 분류와 방문 달력
- 견적 내역 상단에 「전체 / 사전 견적요청 / 방문 견적」 탭.
- 사전요청 상세에 「방문 일정 정하기」(날짜·시간)와 「견적 작성」(고객 입력을 불러와 기존 견적 작성 화면으로).
- 방문 일정은 기존 사전요청 기록에 칸 추가(방문 날짜·시간·상태). 달력에 「고객이름 방문」을 이사 예약과 다른 색으로 표시.

## 4. 예약금·잔금 테두리
- 지금 기준(실제 입금 기록의 상태·금액) 유지. 카드 안에 「예약금 입금 / 잔금 입금」, 입금액, 입금자명, 「확인 필요」 문구 추가.
- 확인 버튼 누른 뒤 테두리 사라짐과 완료 보관함 이동을 실제로 눌러서 확인.

## 5. 고객 화면 색상·브라우저
- 고객 화면 전체(html·body·바깥 틀)에 밝은 모드와 흰 배경 고정, 강제 다크모드 무시 설정.
- 카카오톡·네이버 등 내부 브라우저면 「Chrome으로 열기」 안내(안드로이드는 Chrome 열기 시도, 아이폰은 「외부 브라우저로 열기」 안내). 링크는 운영 https 주소로만 만듭니다.

## 6. 저장·중복
- 지금처럼 요청 하나에 견적 초안 하나만, 고객 수정은 고객 입력 칸만 덮어씀, 확정 후 서버에서 차단. 방문 상태도 서버에 저장해 새로고침·재로그인 후 유지.

## 7. 검증
- 요청하신 13개 항목을 시험 브라우저(휴대폰 크기)로 확인하고, 다른 업체 계정 차단도 확인.
- 확인할 수 없는 것: 실제 삼성 인터넷·카카오톡 앱 안 화면(시험 브라우저는 크롬 기반이라 흉내만 가능). 보고서에 따로 표시합니다.

## 기술 메모
- `intake_requests`에 `visit_date`, `visit_time`, `visit_status` 추가(기본값 있음, 기존 행 영향 없음).
- 품목 조회는 `item-icon.functions.ts`의 공용 헬퍼로 묶고 `listItemIcons`와 `openIntake`가 같이 사용.
- 달력은 기존 계약 달력 서버 조회에 업체 소유 방문 일정을 더해 반환.
- 고객 라우트 head에 `color-scheme: light`, CSS에서 `.jp-intake` 범위 html/body 흰 배경.
