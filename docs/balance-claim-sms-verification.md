# 잔금 신고와 결제 문자 확인

- 실제 김호영 견적은 total=310000, deposit_paid=110000, balance_paid=0이며 확인 예약금 기록만 존재했다. 잔금 은행 SMS 자동 읽기 경로는 없다.
- 고객 화면은 예약금 확인 이후 신고 버튼을 숨겼고, 신고 서버는 예약금만 생성하며 기존 예약금 신고와 중복 처리했다. 잔금 확인 RPC도 customer_claim을 제외했다.
- 고객 신고는 계약 최신 총액에서 확인금액을 차감하고 balance로 기록한다. 미확인 상태는 합산하지 않는다. 예약금과 잔금 중복 키를 분리했다.
- 요청자 로그인, 384×681, 별도 시험 견적: 200000 잔금 신고 → 업체 문자 URI 생성 → 업체 카드 4px rgb(59,130,246) 및 입금자·금액 → 잔금 확인 → 완료 보관, 테두리 제거 → 고객 새로고침 완료 표시.
- 확인 후 고객 결제 문자 준비 함수는 소유자 검증·확인된 기록을 읽어 200000 잔금과 전액 완료 내용을 반환했다. 알리고를 호출하거나 발송 성공 기록을 만들지 않는다.
- 49개 결제·문자 중복방지 규칙 통과. 시험 견적/입금만 정리, 실제 김호영 결제 상태 미변경.
- 실제 문자 앱 전송·통신사 전달·수신은 미검증이다. 고객은 입금 신고 후 업체 문자 보내기, 업체는 입금 확인 후 고객 결제 문자 보내기로 직접 전송한다. 기기 은행 SMS만으로 테두리가 자동 생긴다고 주장하지 않는다.
