# 계좌이체 잔금 표시 확인 (2026-10-19)

## 원인
- 첨부 고객의 실제 견적에는 확인된 예약금 80,000원만 연결되어 있었고 잔금 950,000원 기록은 없었다. 총액 1,030,000원, 잔금 저장값 0원이었다.
- 휴대전화 은행 문자 자동 읽기/은행 거래 조회 연동은 현재 없다. 문자는 기존 입금 기록 영역에서 붙여넣어 등록해야 한다. 이미지나 메모만으로 실제 고객의 결제 기록을 만들지 않았다.

## 변경
- 공통 pendingReceipt는 양수 pending_review 중 bank_transfer만 자동 테두리에 포함한다. 기존 sms_paste/manual의 NULL 수단은 기존 은행 등록 경로로 호환하며 저장값을 바꾸지 않는다. 명시적인 cash/card 및 근거 없는 미분류는 제외한다.
- 계좌이체 확인 화면에 잔금 입금 기록 추가를 연결했다. 기존 등록 영역을 열고 잔금을 선택하고 문자 입력란으로 이동한다.
- 저장 버튼을 잔금/예약금 입금 기록 저장으로 명확히 구분했다. 저장은 확인 완료가 아니며 성공 후 카드 상태를 즉시 재조회한다.
- 현금·카드 완료 로직과 문자 설정, 실제 고객 기록은 변경하지 않았다.

## 실제 인증 화면 시험
- 별도의 세 시험 견적에서 실시하고 시험 데이터만 정리했다.
- 첨부 농협 문자 형식을 입력하여 950,000원, 이다건, balance, bank_transfer, pending_review 저장을 확인했다.
- 등록 즉시 카드에 계좌이체 확인 필요 · 950,000원과 입금자 표시, #FF8A00 4px 테두리를 확인했다.
- 업체 계좌이체 확인 후 완료 보관함 이동, 새로고침 후 계좌이체 완료를 확인했다.
- 현금과 카드 각각 명시적 확인 후 완료, 총액/예약금 불변을 확인했다.
- 기존 estimate_terms, deposit_records, estimate_deliveries, sms_usage_events, move_reminders 조회값 불변. 감시한 문자 전송 요청 0건, 실행 오류 0건.
- 결제 관련 규칙 시험 33개 통과. 현금·카드 양수 미확인 기록의 테두리 제외는 단위 시험으로 검증했다.

## 미지원·미시험
- 은행/실물 휴대전화 문자 자동 읽기는 지원하지 않는다. 실제 고객 잔금은 추가하지 않았다.
- 실제 은행 자동 수신·카드 승인·실물 문자 발송은 시험하지 않았다.
